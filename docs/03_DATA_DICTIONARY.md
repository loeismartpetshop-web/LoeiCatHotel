# Data Dictionary: ข้อมูลที่ระบบต้องเก็บ

Document Type: Data Specification  
Version: 1.0  
Status: Ready for Development

## 1. ข้อมูลธุรกิจและห้อง

### `hotel_settings`

- ชื่อธุรกิจและช่องทางติดต่อ
- timezone: `Asia/Bangkok`
- เวลาเปิด เช็กอิน เช็กเอาต์ และเวลารับกลับสูงสุด
- เพดานแมวรวม 30 ตัว
- อัตรามัดจำ 50%
- เวลา cutoff มัดจำ 24.00 น. วันเดียวกับที่จอง

### `rooms`

- UUID และรหัสห้อง
- ชื่อแสดงผล
- ประเภท `villa`, `condo`, `reserve`
- จำนวนแมวต่ำสุดและสูงสุด
- แสดง/ไม่แสดงในหน้าลูกค้า
- สถานะ `active`, `maintenance`, `inactive`
- ลำดับแนะนำ

## 2. ข้อมูลลูกค้า

### `customers`

- ชื่อ-นามสกุลและชื่อที่ใช้ติดต่อ
- หมายเลขโทรศัพท์
- Mi Home App ID สำหรับแชร์สิทธิ์ดูกล้องห้องพัก (ข้อมูลส่วนบุคคล เห็นได้เฉพาะพนักงานที่ได้รับอนุญาต)
- LINE user ID (เมื่อได้รับจาก LIFF/LINE Login)
- LINE display name (ข้อมูลประกอบ ไม่ใช้เป็นสิทธิ์)
- ช่องทางที่รู้จักธุรกิจ
- ผู้ติดต่อสำรองฉุกเฉิน
- ความยินยอมด้านข้อมูลและการตลาด
- วันเวลาที่สร้างและแก้ไข

## 3. ข้อมูลแมว

### `pets`

- ชื่อ อายุ/วันเกิด เพศ พันธุ์ สี น้ำหนัก และรูปปัจจุบัน
- เลขไมโครชิปถ้ามี
- นิสัย สิ่งที่กลัว พฤติกรรมกัด/ข่วน และประวัติหลบหนี
- อาหาร ปริมาณ เวลา ข้อห้าม และอาการแพ้
- โรคประจำตัวและอาการที่ต้องเฝ้าระวัง
- สัตวแพทย์/โรงพยาบาลสัตว์ประจำ
- หมายเหตุการดูแล

### `pet_medications`

- ชื่อยา ขนาดยา วิธีให้ เวลาเริ่ม/สิ้นสุด
- คำแนะนำพิเศษ
- ผู้บันทึกและสถานะใช้งาน

### `pet_health_documents`

- ประเภทเอกสาร: vaccine, flea_tick, medical, other
- Storage object path (ห้ามเก็บ public URL)
- วันที่ออก/วันหมดอายุหรือวันที่ล่าสุด
- สถานะตรวจสอบ ผู้ตรวจ เวลา และหมายเหตุ

## 4. ข้อมูลการจอง

### `bookings`

- หมายเลขการจองที่มนุษย์อ่านได้
- ลูกค้า ช่องทาง และสถานะ
- วัน/เวลาเช็กอินและเช็กเอาต์
- จำนวนแมวทั้งหมด
- rate plan และราคาต่อหน่วยแบบ snapshot
- จำนวนคืน/ประเภทระยะเวลา
- ยอดรวม มัดจำ ยอดคงเหลือ และสกุลเงิน
- กำหนดชำระมัดจำ
- สถานะเอกสารสุขภาพ
- หมายเหตุลูกค้า/พนักงาน
- แหล่งที่มา: line_oa, web, phone, walk_in, staff

### `booking_pets`

- ความสัมพันธ์ระหว่าง booking และ pets
- snapshot คำแนะนำอาหาร ยา และข้อควรระวัง ณ วันจอง

### `booking_room_allocations`

- booking, room, วันที่เริ่มและสิ้นสุด
- จำนวนแมวที่จัดในห้อง
- สถานะการจัดห้อง
- ผู้จัด/เปลี่ยนห้องและเหตุผล

### `booking_status_history`

- สถานะก่อนและหลัง
- เหตุผล
- ผู้ดำเนินการ/ช่องทางอัตโนมัติ
- วันเวลา

## 5. การเงิน

### `payments`

- booking และประเภท `deposit`, `balance`, `other`
- จำนวน วิธีชำระ ผู้ให้บริการ และ reference
- สถานะ `pending`, `paid`, `failed`, `voided`
- วันเวลาชำระและหลักฐาน

### `refund_requests`

- booking/payment ที่อ้างอิง
- จำนวนที่ร้องขอและเหตุผล
- สถานะ `requested`, `under_review`, `approved`, `rejected`, `refunded`
- ผู้อนุมัติ วันเวลา และหลักฐาน

## 6. การปฏิบัติงาน

### `care_tasks`

- booking/pet ที่เกี่ยวข้อง
- ประเภท: food, water, medication, cleaning, play, photo_update, other
- กำหนดเวลา ผู้รับผิดชอบ สถานะ และหลักฐาน

### `notifications`

- ผู้รับ ช่องทาง template และ payload
- สถานะการส่ง attempts และ provider reference
- เวลาที่กำหนด/ส่งจริง

### `audit_logs`

- actor, action, entity, entity_id
- before/after summary ที่ไม่เก็บ secret
- IP/user agent เมื่อเหมาะสม
- วันเวลา

## 7. ข้อมูลที่ห้ามเก็บแบบไม่จำเป็น

- รหัสผ่าน LINE หรือรหัสผ่านธนาคาร
- เลขบัตรเต็มหรือข้อมูลบัตรชำระเงิน
- service role/secret key ในฐานข้อมูลหรือ frontend
- public URL ถาวรของเอกสารสุขภาพ
- ข้อมูลสุขภาพที่ไม่เกี่ยวกับการดูแลแมว
